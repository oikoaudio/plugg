Plugg 0.2.0 publishes plug-ins as VST2 and CLAP as well as VST3. It also handles installers that install only their vendor's app, such as Plugin Alliance's.

This is still a developer preview. It works on the maintainer's system (CachyOS, Hyprland, Bitwig) with the vendors in the [compatibility notes](https://github.com/oikoaudio/plugg/tree/v0.2.0/docs/compatibility). Not every plug-in will work.

## Install

- Ubuntu 24.04 or newer, Debian 13 or newer: download `plugg_0.2.0_amd64.deb` below, then `sudo apt install ./plugg_0.2.0_amd64.deb`
- Fedora 42 or newer: download `plugg-0.2.0-1.x86_64.rpm` below, then `sudo dnf install ./plugg-0.2.0-1.x86_64.rpm`
- Arch and Arch-based systems: download `plugg-0.2.0-1-x86_64.pkg.tar.zst` below, then `sudo pacman -U ./plugg-0.2.0-1-x86_64.pkg.tar.zst`

To update from 0.1.0, install the new package over the old one. Your library and the plug-ins already in your DAW stay as they are.

## VST2 and CLAP

- Switch on VST2, CLAP or both under Settings. VST3 is always on.
- VST2 is for reopening projects that saved their plug-ins as VST2, such as projects made on Windows. CLAP is for DAWs that prefer it.
- VST2 plug-ins go to `~/.vst/plugg` and CLAP plug-ins to `~/.clap/plugg`. If your DAW doesn't scan those folders, add them to its plug-in locations.
- Switching a format on publishes nothing by itself, because Plugg checks a plug-in by loading it and loading an unactivated plug-in can open its activation window. Plug-ins you already have get the new format when you use **Check again** or **Refresh library** on their vendor.
- Switching a format off never removes a plug-in that is already published, so an old project that needs it keeps working.
- You can drop a VST2 `.dll` or a CLAP `.clap` on the window, as you can a `.vst3`. It is published in its own format even if that format is switched off.
- Only 64-bit plug-ins are supported. Plugg skips 32-bit VST2 and CLAP files.

## Vendor apps

- Some installers install only their vendor's app and no plug-ins. Plugin Alliance's Installation Manager is one. Plugg now gives that app a button on the vendor's row and tells you to open it. Before, it reported that no plug-ins were found.
- Plugg attaches an app by itself only when it is sure which program it is. Otherwise the installation's card asks you to choose, with **Choose app…**.
- **Change app…** in a vendor's settings menu (the cogwheel) replaces an app Plugg attached. 0.1.0 could attach the copy of a setup program that an installer keeps for repairs, shown on the vendor's row as **Run installer**. Use **Change app…** to pick the vendor's real app instead.

## Fixes

- Dropping a file from Dolphin on Wayland works.
- When you add an installer or plug-in from Cytomic, Plugg warns that it cannot be authorised under Plugg yet. The [compatibility notes](https://github.com/oikoaudio/plugg/tree/v0.2.0/docs/compatibility) have the details.
- When an installation finds no plug-ins, the message no longer names a format. If the only plug-ins it found are in a format that is switched off, it says which one and points to Settings.

## Plugg has no helpdesk

One person makes Plugg. Good bug reports get read and fixed. To send one, open Help in the app and choose Report a bug in Plugg. The form asks for what makes a report useful. A request to get one particular setup working usually can't be answered.

## Files

- `.deb`, `.rpm` and the generic tarball hold the app, the prebuilt plug-in bridge and the PowerShell forwarder. The bridge needs glibc 2.34 or newer. It now includes yabridge's VST2 and CLAP bridges.
- The Arch package holds the same app, with a bridge compiled on Arch from the same tag.
- `plugg-bridge-0.2.0-x86_64.tar.gz` is the bridge on its own, with its licences.
- The wheel is the Python package. Installed with pipx, it downloads the bridge above on first use.
- `SHA256SUMS` lists every file's checksum.
