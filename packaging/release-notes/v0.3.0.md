Plugg 0.3.0 uses the `plugg-2` runtime in new libraries, so a first install needs no runtime commands for Kontakt 8 or iLok. It also fixes `plugg prepare`.

This is still a developer preview. It works on the maintainer's system (CachyOS, Hyprland, Bitwig) with the vendors in the [compatibility notes](https://github.com/oikoaudio/plugg/tree/v0.3.0/docs/compatibility). Not every plug-in will work.

## Install

- Ubuntu 24.04 or newer, Debian 13 or newer: download `plugg_0.3.0_amd64.deb` below, then `sudo apt install ./plugg_0.3.0_amd64.deb`
- Fedora 42 or newer: download `plugg-0.3.0-1.x86_64.rpm` below, then `sudo dnf install ./plugg-0.3.0-1.x86_64.rpm`
- Arch and Arch-based systems: download `plugg-0.3.0-1-x86_64.pkg.tar.zst` below, then `sudo pacman -U ./plugg-0.3.0-1-x86_64.pkg.tar.zst`

To update from 0.2.3, 0.2.2 or 0.2.1, install the new package over the old one. Your library and the plug-ins already in your DAW stay as they are.

If you are updating from 0.2.2 or 0.2.1, close your DAW and run `plugg environment update-launcher`. The session fix in 0.2.3 reaches an existing environment only through that command. It changes the environment's launcher and leaves its Windows prefix and machine identity alone.

## New libraries

A new library selects `plugg-2`. Plugg downloads its modules, checks their hashes and assembles it the first time it needs a runtime, so you can install Kontakt 8 without any runtime commands.

If the download fails, setup stops and asks you to check your connection. Plugg does not fall back to plain Proton, because that environment would lack the fixes and give no sign of it.

## Existing libraries

A library made before 0.3.0 keeps its selected runtime, or plain UMU-Proton 10.0-4 if it has none. Its environments stay as they are. To use `plugg-2` for new environments:

```sh
plugg runtime assemble plugg-2
plugg runtime select plugg-2
```

A runtime applies to environments created after you select it. Kontakt 8 needs a Native Access environment created on `plugg-2`, which means signing in and installing your products again.

## iLok

In a new library, `plugg ilok create` needs no runtime commands. iLok sign-in and activation work on `plugg-2`, tested by activating one plug-in, Pulsar Audio W495. Nobody has played an activated plug-in on it yet.

`plugg-1` has the longer record, and [iLok and PACE](https://github.com/oikoaudio/plugg/blob/v0.3.0/docs/recipes/pace.md) shows how to choose it. A library made before 0.3.0 with no runtime selected has to select one before `plugg ilok create`.

## plugg prepare

`plugg prepare` downloaded a Wine build that no new environment uses, and it failed on an empty cache. It now runs the same setup as an install.

## Plugg has no helpdesk

One person makes Plugg. Good bug reports get read and fixed. To send one, open Help in the app and choose Report a bug in Plugg. The form asks for what makes a report useful. A request to get one particular setup working usually can't be answered.

## Files

- `.deb`, `.rpm` and the generic tarball hold the app, the prebuilt plug-in bridge and the PowerShell forwarder. The bridge needs glibc 2.34 or newer.
- The Arch package holds the same app, with a bridge compiled on Arch from the same tag.
- `plugg-bridge-0.3.0-x86_64.tar.gz` is the bridge on its own, with its licences.
- The wheel is the Python package. Installed with pipx, it downloads the bridge above on first use.
- `SHA256SUMS` lists every file's checksum.
