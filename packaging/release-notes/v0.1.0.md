This is the first release of Plugg, which puts your Windows audio plug-ins in your Linux DAW. Drop in a vendor's installer or a Windows VST3, and Plugg installs it into a private Windows environment and adds it to your DAW as a native VST3.

This is a developer preview. It works on the maintainer's system (CachyOS, Hyprland, Bitwig) with the vendors in the [compatibility notes](https://github.com/oikoaudio/plugg/tree/v0.1.0/docs/compatibility). Not every plug-in will work.

## Install

- Ubuntu 24.04 or newer, Debian 13 or newer: download `plugg_0.1.0_amd64.deb` below, then `sudo apt install ./plugg_0.1.0_amd64.deb`
- Fedora 42 or newer: download `plugg-0.1.0-1.x86_64.rpm` below, then `sudo dnf install ./plugg-0.1.0-1.x86_64.rpm`
- Arch and Arch-based systems: download `plugg-0.1.0-1-x86_64.pkg.tar.zst` below, then `sudo pacman -U ./plugg-0.1.0-1-x86_64.pkg.tar.zst`

Start Plugg from your applications menu, or run `plugg gui`. Plugg downloads its Proton runtime the first time it needs it and checks it by hash.

## What's in it

- One Windows environment per vendor, set up from the vendor's own installer or a VST3 file.
- Vendor apps open from the vendor's row: Native Access, UA Connect, Klevgrand Helper, Kilohearts Installer and others. Close the app, and Plugg adds what it installed.
- iLok plug-ins share one environment that iLok sees as one computer. Creating it is still an experimental command-line step (`plugg ilok create`).
- Plugg records which environments hold licence activations and asks for a typed confirmation before deleting one.
- Help in the app: an FAQ, what is already known about an installer as you add it, and a guided form for good bug reports.
- Works from the keyboard and with a screen reader, and follows your desktop's text size and contrast settings.

## Plugg has no helpdesk

One person makes Plugg. Good bug reports get read and fixed. To send one, open Help in the app and choose Report a bug in Plugg. The form asks for what makes a report useful. A request to get one particular setup working usually can't be answered.

## Files

- `.deb`, `.rpm` and the generic tarball hold the app, the prebuilt plug-in bridge and the PowerShell forwarder. The bridge needs glibc 2.34 or newer.
- The Arch package holds the same app, with a bridge compiled on Arch from the same tag.
- `plugg-bridge-0.1.0-x86_64.tar.gz` is the bridge on its own, with its licences.
- The wheel is the Python package. Installed with pipx, it downloads the bridge above on first use.
- `SHA256SUMS` lists every file's checksum.
