Plugg 0.2.3 makes Kontakt 8 installable, fixes two ways a plug-in could fail to load or publish, and detects any DAW.

This is still a developer preview. It works on the maintainer's system (CachyOS, Hyprland, Bitwig) with the vendors in the [compatibility notes](https://github.com/oikoaudio/plugg/tree/v0.2.3/docs/compatibility). Not every plug-in will work.

## Install

- Ubuntu 24.04 or newer, Debian 13 or newer: download `plugg_0.2.3_amd64.deb` below, then `sudo apt install ./plugg_0.2.3_amd64.deb`
- Fedora 42 or newer: download `plugg-0.2.3-1.x86_64.rpm` below, then `sudo dnf install ./plugg-0.2.3-1.x86_64.rpm`
- Arch and Arch-based systems: download `plugg-0.2.3-1-x86_64.pkg.tar.zst` below, then `sudo pacman -U ./plugg-0.2.3-1-x86_64.pkg.tar.zst`

To update from 0.2.2 or 0.2.1, install the new package over the old one. Your library and the plug-ins already in your DAW stay as they are.

After updating, close your DAW and run `plugg environment update-launcher`. The session fix below reaches an existing environment only through that command. It changes the environment's launcher and leaves its Windows prefix and machine identity alone.

## Kontakt 8

Kontakt 8 needs the new `plugg-2` runtime. On `plugg-1`, Native Access reports that it installed and no file exists, because Wine damages the large MSI inside Kontakt's installer when the installer saves it. `plugg-2` carries the fix, and Kontakt 8 Player 8.14.1 installs, activates and plays on it in Bitwig.

```sh
plugg runtime assemble plugg-2
plugg runtime select plugg-2
```

A runtime applies to environments created after you select it. An existing Native Access environment stays on its runtime, so Kontakt 8 needs a Native Access environment created on `plugg-2`, which means signing in and installing your products again.

`plugg-2` also carries the upstream Wine fix that lets Wine report some crashes it used to die on without a message.

`plugg ilok create` now accepts `plugg-1` or `plugg-2`. PACE 6.0.1 installs on `plugg-2` and its service runs. Nobody has signed in to iLok or activated a plug-in on it yet, so `plugg-1` is still the tested choice for iLok.

## Plug-ins that failed to load

An environment's Proton session kept the working folder of the first plug-in host that started it. A DAW that removes a host's folder when the host ends left the session in a folder that no longer existed, and every later plug-in from that environment failed to load, in any DAW. The session now runs from its environment folder.

## Plug-ins that stayed out of your DAW

Closing Native Access could stop with "Another runtime is still using this vendor environment", and a new plug-in stayed "not in your DAW yet". Plugg now waits for Wine to finish exiting before it refuses. If you see that message on an older version, choose Refresh library.

## Closing your DAW

Plugg used to look for processes named Bitwig or REAPER, so other DAWs passed unnoticed and an idle Bitwig blocked force close and vendor setup. It now checks whether any process has a Windows plug-in loaded through the bridge, whatever the DAW is called. A DAW with nothing loaded no longer blocks anything, and the drop area shows a note while plug-ins are loaded.

Plugg cannot detect a DAW with nothing loaded, so close your DAW before you install or update plug-ins.

## Plugg has no helpdesk

One person makes Plugg. Good bug reports get read and fixed. To send one, open Help in the app and choose Report a bug in Plugg. The form asks for what makes a report useful. A request to get one particular setup working usually can't be answered.

## Files

- `.deb`, `.rpm` and the generic tarball hold the app, the prebuilt plug-in bridge and the PowerShell forwarder. The bridge needs glibc 2.34 or newer.
- The Arch package holds the same app, with a bridge compiled on Arch from the same tag.
- `plugg-bridge-0.2.3-x86_64.tar.gz` is the bridge on its own, with its licences.
- The wheel is the Python package. Installed with pipx, it downloads the bridge above on first use.
- `SHA256SUMS` lists every file's checksum.
